# CardioGuard (Android · Kotlin/Compose) — оригинальный прототип

> Это исходная нативная Android-версия CardioGuard на Kotlin + Jetpack Compose.
> Активная разработка ведётся в кросс-платформенной версии (`mobile/`, React
> Native + Expo) — см. корневой [README](../README.md). Данный модуль сохранён
> как первоисточник портированной клинической логики и как артефакт
> диссертационной работы.

CardioGuard — это полнофункциональный клинико-технологический прототип медицинского программного комплекса, спроектированного для непрерывного мониторинга кардиометаболического здоровья, повышения приверженности медикаментозной терапии и превентивного снижения риска сердечно-сосудистых заболеваний (ССЗ).

Данный проект разработан как экспериментальная демонстрационная платформа в рамках академической диссертационной работы по специальности «Медицинская информатика и превентивные информационные системы».

---

## 1. Целевое назначение и структура системы

Информационная система CardioGuard призвана решить проблему недостаточного участия пациентов в контроле хронических неинфекционных заболеваний и преодолеть низкую приверженность лечению (комплаентность). Разработка предоставляет:
1. **Индивидуальным пользователям (Пациентам):** Удобные мобильно-ориентированные инструменты самоконтроля физиологических констант, динамический мониторинг веса/ИМТ, графическое представление АД и ЧСС, а также персонализированные гигиенические рекомендации в зависимости от условий труда (включая группы профессионального риска спасателей, военнослужащих и работников силовых ведомств с ненормированным графиком дежурств).
2. **Медицинским исследователям и врачам:** Деперсонализированные сводные реестры когортного наблюдения, позволяющие агрегировать показатели систолического АД, среднего ИМТ и общей приверженности для выявления групповых закономерностей.
3. **Рецензентам и аттестационной комиссии:** Чёткую, прозрачную программную архитектуру, воспроизводимый поток данных (Data Flow), научно обоснованные калькуляторы SCORE2/Framingham и работающий сигнальный контур раннего предупреждения.

## 2. Архитектура программных модулей

Система CardioGuard построена по каноническому паттерну проектирования **MVVM (Model-View-ViewModel)** на мобильном стеке **Kotlin + Jetpack Compose + StateFlow** (Material Design 3):

```
                                  [ ЭКРАН КЛИЕНТА (UI) ]
                         (Compose Screens: Dashboard, Charts, Forms)
                                            │
                                            ▲  Реактивно слушает (StateFlow)
                                            │
                                    [ VIEWMODEL ENGINE ]
                               (MainViewModel: State, Triggers)
                                            │
                   ┌────────────────────────┴────────────────────────┐
                   ▼                                                 ▼
          [ ПОДСИСТЕМА АНАЛИЗА ]                           [ ХРАНИЛИЩЕ ДАННЫХ ]
         (MedicalCalculators.kt)                            (MockData / State)
```

### Основные функциональные модули:
1. **Onboarding Wizard (Подсистема первичного анкетирования):** Пятиэтапный опросник, регистрирующий паспортно-клинические данные, отягощенность наследственными заболеваниями ССЗ и режим профессионального труда.
2. **Health Monitoring (Телемониторинг):** Модуль сбора дневниковых данных. Включает автоматическое определение ИМТ на лету и интерпретацию уровней артериального давления по рекомендациям РКО/ESC.
3. **Medication Adherence (Контроль комплаентности):** Динамический планировщик приема лекарственных препаратов с функцией обратной связи. На основе отметок рассчитывается коэффициент приверженности.
4. **CVD Risk Assessment (Калькулятор риска):** Интегральный расчет вероятности развития инфаркта миокарда или инсульта в течение 10 лет с использованием прототипных алгоритмов SCORE2 (для европейского региона) и Framingham Risk.
5. **Early Warning System (Сигналы раннего предупреждения):** Контур автоматического клинического скрининга. Отслеживает критические пороги АД, резкую динамику прибавки веса, падение дисциплины удержания терапии и формирует сигнальные карточки.
6. **Aggregated Researcher Panel (Панель аналитики):** Научно-исследовательский дашборд с деперсонализированной выборкой пациентов для статистической оценки эффективности профилактики.

## 3. Спецификация структуры данных (Data Models)

Проект использует строго типизированные модели данных, находящиеся в пакете `com.example.data.Models`:

### `UserProfile` (Клинический профиль)
* `id: String` — сквозной идентификатор;
* `anonymizedId: String` — деперсонализированный код пациента для защиты персональных данных согласно ФЗ-152;
* `fullName: String` — имя;
* `age: Int` — возраст;
* `sex: String` — биологический пол («Мужской», «Женский»);
* `heightCm: Double` — рост (см);
* `weightKg: Double` — вес (кг);
* `waistCircumferenceCm: Double` — окружность талии;
* `smokingStatus: String` — статус курения;
* `diabetesStatus: String` — наличие сахарного диабета;
* `hypertensionStatus: String` — наличие артериальной гипертонии;
* `onHypertensiveMedication: Boolean` — факт приёма гипотензивных средств;
* `familyHistoryCVD: String` — семейная отягощенность ССЗ;
* `workScheduleType: String` — тип работы (Обычный график, сменный, ночной);
* `professionalRiskGroup: String` — профессиональная группа риска;
* `physicalActivityLevel: String` — физическая активность;
* `sleepQuality: String` — качество сна.

### `HealthMeasurement` (Единичный замер)
* `id: String`, `userId: String` — ключи соответствия;
* `date: Date` — временная отметка;
* `systolicBP: Int` — систолическое АД (мм рт. ст.);
* `diastolicBP: Int` — диастолическое АД (мм рт. ст.);
* `heartRate: Int` — пульс (уд/мин);
* `weightKg: Double`, `bmi: Double` — весовые характеристики;
* `waistCircumferenceCm: Double` — локальный абдоминальный замер;
* `sleepHours: Double` — длительность сна;
* `stressLevel: String` — текущий психоэмоциональный уровень;
* `physicalActivityMinutes: Int` — аэробная нагрузка (мин).

## 4. Клиническая логика и превентивные правила

### Законы сбора и интерпретации констант:
* **Индекс массы тела (ИМТ):**
  $$ИМТ = \frac{Вес\ (кг)}{(Рост\ (м))^2}$$
  Категоризация по ВОЗ: `<18.5` — Дефицит массы, `18.5-24.9` — Норма, `25.0-29.9` — Избыточный вес, `>=30.0` — Ожирение.
* **Классификация артериального давления (РКО/ESC):**
  * САД `< 120` и ДАД `< 80` — Оптимальное АД;
  * САД `120-129` или ДАД `80-84` — Нормальное АД;
  * САД `130-139` или ДАД `85-89` — Высокое нормальное АД;
  * САД `>= 140` или ДАД `>= 90` — Артериальная гипертензия.

### Контур раннего предупреждения (Alert Engine Triggers):
1. **Острый замер давления:** САД `>= 140` или ДАД `>= 90` мм рт. ст. $\to$ Тревога уровня «Внимание».
2. **Привычный подъем АД:** Наличие $\ge 2$ завышенных результатов АД в течение последних 7 дней $\to$ «Высокий приоритет».
3. **Задержка тканевой жидкости:** Прирост веса на $\ge 2$ кг по сравнению с предыдущим замером $\to$ Тревога гидролабильности (риск декомпенсации миокарда).
4. **Гипотензивные пропуски:** Падение уровня медикаментозной комплаентности ниже `70%` $\to$ Тревога «Высокий приоритет».

## 6. Как запустить и протестировать прототип

1. **Запуск**: После старта приложения вы попадете на клинический экран приветствия (`AuthScreen`). На нем представлены удобные демонстрационные кнопки быстрого входа:
   * **Пользователь** — мгновенно активирует профиль пациента с предопределенной историей 14-ти дневного мониторинга.
   * **Врач/Наука** — переведет в режим исследователя когортной группы.
2. **Экспорт**: На панели врача доступна интерактивная кнопка «Экспорт CSV», имитирующая создание файла деперсонализированного регистра для R/Python статистического анализа.
3. **Анкетирование**: Нажмите «Сброс» в настройках, чтобы пройти интерактивный onboarding с нуля с кастомными физиологическими показателями.
